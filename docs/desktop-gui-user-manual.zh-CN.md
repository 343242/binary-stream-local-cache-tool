# 桌面 GUI 操作手册

本文档说明当前桌面端 GUI 的实际使用方式。内容以当前 `development` 分支上的真实实现为准。

## 1. 适用范围

当前桌面端是一个本地、以观测为先的缓存检查控制台，主要用于：

- 打开一个本地缓存根目录
- 查看工作区总览
- 浏览段文件、WAL、游标、检查点
- 审计只读配置
- 执行带门禁的 `verify / close-check / repair-tail / shutdown`

它不是配置编辑器，也不是通用文件浏览器。

## 2. 启动前准备

### 2.1 Linux

如果已经完成 Wails 原生构建，可从仓库根目录启动：

```bash
cd /home/instant/projects/fastReadFile
./build/bin/binary-stream-cache-tool
```

如果当前环境是无桌面会话或需要 headless 冒烟启动，可使用：

```bash
cd /home/instant/projects/fastReadFile
dbus-run-session -- xvfb-run -a ./build/bin/binary-stream-cache-tool
```

### 2.2 Windows

如果已经在 Windows 上完成 `wails build -platform windows/amd64`，可从项目根目录启动：

```powershell
cd E:\Servlet\fastReadFile
.\build\bin\binary-stream-cache-tool.exe
```

## 3. 工作区要求

桌面端只接受“缓存根目录”作为工作区。当前实现期望目录下存在缓存运行结构，例如：

- `segments/`
- `wal/`
- `meta/`
- `meta/replay/`

如果选择的目录不符合要求，界面会停留在起始页，并提示这不是一个有效的缓存工作区。

## 4. 界面结构

主界面由三部分组成：

- 左侧 `Sidebar`
  - 显示产品名、工作区状态、主导航
- 顶部 `TopBar`
  - 显示当前快照路径、模式、锁状态、健康度、刷新按钮、语言切换按钮
- 主内容区
  - 根据当前页面显示 `Landing / Overview / Explorer / Config / Operations`

## 5. 默认语言与切换

- 当前默认语言是 `中文`
- 顶部栏中有一个语言切换按钮
  - 当按钮显示 `EN` 时，点击后切换为英文
  - 当按钮显示 `中文` 时，点击后切换为中文

注意：

- 当前切换语言后，前端静态文案会同步切换
- 某些来自 backend 的自由文本消息如果本身不是字典项，可能保持原始语言

## 6. 起始页（Landing）

在尚未打开工作区时，应用会停留在起始页。

你可以在这里执行 3 类操作：

1. `打开缓存目录`
   - 打开原生目录选择器
   - 选择有效缓存根目录后，应用会进入工作区加载流程

2. 查看“支持的工作区”
   - 这里说明当前 GUI 期望打开的目录类型

3. 使用“最近目录”
   - 点击 `重新打开` 可直接重新打开最近使用过的缓存目录

如果当前工作区无效：

- 起始页会显示“这不是一个缓存工作区”
- 点击 `重新选择目录` 可再次打开目录选择器

## 7. 无工作区时的导航门禁

在没有成功打开缓存目录之前：

- `Overview` 作为默认落地页可见
- `Explorer / Config / Operations` 不允许进入

如果此时点击这些导航项：

- 页面不会切换
- 右上侧会出现一条友好提示
- 提示内容会要求你先打开缓存目录

这是当前产品的刻意门禁，不是异常。

## 8. 工作区加载与刷新

选择缓存目录后，应用会进入加载流程：

- 顶栏出现“正在打开工作区”
- 主内容区出现加载骨架屏
- 完成后自动进入实际工作区视图

点击顶部 `刷新` 按钮可以重新拉取当前工作区快照。

如果是破坏性操作前的刷新需求，建议先确认：

- 顶栏状态正常
- 侧栏状态不是“陈旧快照”

## 9. 概览页（Overview）

概览页用于快速判断当前工作区是否适合继续深入检查或进入维护动作。

### 9.1 你会看到什么

- 优先快照卡片
  - 工作区模式
  - 锁状态
  - 存储占用
  - 重放进度
  - 检查点 / fsync 摘要
  - 告警数量

- 告警与操作员注意事项
  - 用于快速发现会阻止维护交接的问题

- 最近活动
  - 最近段文件
  - 最近游标

### 9.2 如何使用

建议先看：

1. 工作区模式
2. 锁状态
3. 是否存在告警
4. 最近段文件和游标状态

如果这里已经出现明显异常，再进入 `Explorer` 或 `Operations`。

## 10. 浏览器页（Explorer）

浏览器页用于查看更具体的只读细节。

### 10.1 四个视角

- `段文件`
- `WAL`
- `游标`
- `检查点`

### 10.2 段文件视角

左侧是行账本，显示：

- 段文件 ID
- 大小
- 最新写入序号
- 记录数

点击某一行后：

- 右侧详情面板更新
- 会显示段文件标识、写入范围、完整性、原始预览等字段

### 10.3 WAL 视角

如果存在 WAL：

- 右侧会显示 WAL 路径、大小、健康度、批次范围、末尾偏移等信息

如果不存在：

- 左侧和右侧都会显示空态提示

### 10.4 游标视角

左侧列表显示：

- destination
- writeSeq
- status

点击游标后：

- 右侧会显示游标位置、偏移、记录索引、CRC 状态、备份状态

### 10.5 检查点视角

如果存在检查点：

- 右侧会显示最后批次序号、最后 WAL 偏移、版本、更新时间、完整性状态

如果不存在：

- 会显示空态提示

## 11. 配置页（Config）

配置页当前是只读审计账本。

你可以看到：

- 配置分组
- 当前生效值
- 启动默认值
- 允许范围
- 审计备注

当前不能直接在 GUI 中修改配置。

这个页面更适合：

- 审计部署参数
- 对照默认值
- 检查启动期配置是否偏离预期

## 12. 操作页（Operations）

操作页按风险分为两组：

- 只读动作
  - `校验`
  - `关闭检查`

- 破坏性维护动作
  - `修复尾部`
  - `停机`

### 12.1 只读动作

只读动作不需要进入危险确认弹窗，可直接执行。

执行后会看到：

- 任务时间线
- 最近结果
- 顶层通知（Toast）

### 12.2 破坏性动作

破坏性动作会先检查前置条件，例如：

- 工作区姿态是否为维护模式
- 锁是否为 `MaintenanceExclusive`
- 快照是否为新鲜快照
- 是否已选择修复目标段文件

如果条件不满足：

- 操作不会继续
- 页面会显示“在确认前被阻止”

如果条件满足：

- 按钮会显示为 `审查影响`
- 点击后进入确认弹窗

### 12.3 确认弹窗

确认弹窗用于再次确认风险影响。

你会看到：

- 动作名称
- 风险级别
- 影响摘要
- 影响列表
- 取消与确认按钮

只有确认后，后台任务才会真正启动。

### 12.4 任务时间线

任务时间线会显示：

- 已请求
- 进行中
- 已完成 / 失败 / 已取消

还会显示：

- 任务类型
- 生命周期
- 阶段
- 消息
- 进度
- 起止时间
- 错误信息

如果当前任务支持取消，会出现 `取消任务` 按钮。

### 12.5 最近结果

最近结果与任务时间线分离展示。

这里主要用于看：

- 最终摘要
- 返回字段
- 是否出现 `打开修复` 按钮

例如：

- `校验` 发现可修复损坏时，会给出 `打开修复`
- 点击后可直接把操作页切换到 `修复尾部`

## 13. Toast 通知说明

当前通知会显示在主界面右上区域。

通知通常包含：

- 标题
- 提示类型
- 详细说明
- 持续时间

典型场景：

- 无工作区时点击受门禁导航
- 任务完成
- 任务失败
- 发现可修复问题

## 14. 常见状态说明

### 14.1 未打开工作区

表示还没有选择有效缓存目录。

表现：

- 侧栏显示“未打开工作区”
- 起始页可见
- 其他导航被门禁

### 14.2 无效工作区

表示你选择的目录不符合缓存工作区结构。

表现：

- 起始页出现错误提示
- 可以重新选择目录

### 14.3 新鲜快照

表示当前前端快照可用于正常观察和决策。

### 14.4 陈旧快照

表示当前快照可能过时。

表现：

- 侧栏或操作前置条件会显示“陈旧快照”
- 破坏性动作会被阻止，要求先刷新

### 14.5 降级只读

表示 backend 或工作区状态不允许进入正常维护流，只能保守只读处理。

## 15. 小屏与滚动行为

当前桌面端已经改成“保持桌面布局，不因屏幕过小而自动改单列”。

也就是说：

- 侧栏、顶部栏、Explorer 双栏、Operations 双栏会保持原结构
- 如果屏幕宽度不足，不会压成手机样式
- 这时请直接使用系统滚动条查看被遮挡区域

这是一项刻意设计，目的是避免在小屏下把运维界面改造成另一套布局。

## 16. 已知限制

当前版本仍有这些限制：

- 某些 backend 返回的自由文本尚未完全字典化，切换语言后可能保持原始语言
- 配置页仍然只读，不能直接编辑配置
- 当前桌面二进制仍建议从仓库根目录启动
- 若前端资源未完成构建，Wails 原生启动会失败
- Windows 原生构建仍需在 Windows 主机上单独验证运行环境

## 17. 推荐使用顺序

如果你是第一次使用当前 GUI，建议按这个顺序操作：

1. 启动桌面端
2. 在起始页点击 `打开缓存目录`
3. 先看 `概览`
4. 再进入 `浏览器` 查看段文件、WAL、游标或检查点
5. 最后仅在确认姿态、锁和快照状态都正确时，再进入 `操作`

这样可以减少在信息不完整时直接进入高风险动作的概率。
